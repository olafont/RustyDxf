# RustyDxf — by art-tech

A small, fast DXF **viewer** (no editing) written in Rust with egui and wgpu,
with a built-in [MCP](https://modelcontextprotocol.io) server so AI clients can
inspect, measure and render drawings.

- App ID: `dev.art-tech.rustydxf`
- Platforms: macOS (tested), Windows and Linux (compile-checked only, see
  [Known limitations](#known-limitations))

## Build

Requires Rust 1.95 or newer (edition 2024; `rust-toolchain.toml` pins 1.99.1).

```sh
cargo build --release            # binary: target/release/rustydxf
cargo run --release -- file.dxf  # open a drawing
cargo test --workspace           # unit, fixture, render and MCP tests
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
```

Workspace layout:

| Crate | Contents |
|---|---|
| `core/` (`rustydxf-core`) | No UI. DXF loading into its own `Drawing` model, tessellation, the wgpu pipeline (on-screen and offscreen PNG), queries |
| `app/` (`rustydxf`) | The viewer (eframe/egui), platform integration, the MCP server |
| `xtask/` | `cargo xtask icons` and `cargo xtask bundle` |

Test fixtures in `tests/fixtures/` are generated by `core/src/fixtures.rs`
(the tests regenerate them). Put real-world drawings in `tests/fixtures/real/`.

Render tests are skipped on machines with no GPU adapter unless
`RUSTYDXF_REQUIRE_GPU=1` is set.

## Usage

```
rustydxf [FILE.dxf]                    open the viewer
rustydxf --mcp                         MCP server over stdio
rustydxf --mcp --http 127.0.0.1:PORT   MCP server over Streamable HTTP (loopback only)
rustydxf --register                    make RustyDxf the default app for .dxf
rustydxf --mcp-config                  print the MCP client config for this install
```

| Action | Input |
|---|---|
| Zoom about the cursor | Mouse wheel, trackpad pinch |
| Pan | Middle-drag, Space + drag, left-drag, trackpad two-finger scroll |
| Zoom to extents | `F` |
| Open / close | Cmd/Ctrl+O, Cmd/Ctrl+W, or drop a file on the window |

Only one viewer window runs at a time: starting `rustydxf file.dxf` again hands
the file to the running window.

Logs go to stderr (`RUST_LOG=debug` for more). In MCP stdio mode stdout carries
only the protocol.

## macOS app bundle

```sh
cargo xtask bundle          # release build → dist/RustyDxf.app
cargo xtask bundle --debug  # same, from a debug build
```

The bundle is assembled by `xtask` (not cargo-bundle): it writes `Info.plist`
(`CFBundleDocumentTypes` for `.dxf` as Viewer/Owner, and a
`UTImportedTypeDeclarations` entry for `com.autodesk.dxf` conforming to
`public.data`), copies the icon, and ad-hoc signs the result. Copy
`dist/RustyDxf.app` to `/Applications` before registering.

Files opened from Finder arrive as Apple Events on both cold and warm launch.

## Registering as the default .dxf app

**macOS** — run the binary inside the bundle:

```sh
/Applications/RustyDxf.app/Contents/MacOS/rustydxf --register
```

This runs `lsregister -f` on the bundle and sets the default handler for
`com.autodesk.dxf`. If macOS does not accept the change, do it by hand: select a
`.dxf` in Finder → Get Info → Open with → RustyDxf → Change All.

**Windows** — `rustydxf.exe --register` writes per-user keys under
`HKCU\Software\Classes` (ProgID `ArtTech.RustyDxf.Drawing`, `.dxf` →
OpenWithProgids), notifies the shell, and opens Settings → Default apps, where
Windows requires you to confirm the choice yourself.

**Linux** — `rustydxf --register` installs
`dev.art-tech.rustydxf.desktop` and a MIME definition for `image/vnd.dxf` under
`~/.local/share`, runs `update-mime-database` and `update-desktop-database`,
then `xdg-mime default`.

## MCP server

`rustydxf --mcp` speaks MCP over stdio and opens no window unless a tool asks
for one. `--http 127.0.0.1:PORT` serves Streamable HTTP at `/mcp`; non-loopback
addresses are refused and requests with a non-local `Host` get a 403.

In the viewer, **Help → Copy MCP config** copies the JSON below with the right
path filled in (`rustydxf --mcp-config` prints it).

**Claude Desktop** — add to `claude_desktop_config.json`
(macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`):

```json
{
  "mcpServers": {
    "rustydxf": {
      "command": "/Applications/RustyDxf.app/Contents/MacOS/rustydxf",
      "args": ["--mcp"]
    }
  }
}
```

**Claude Code**

```sh
claude mcp add rustydxf -- /Applications/RustyDxf.app/Contents/MacOS/rustydxf --mcp
```

### Tools

Paths must be absolute; a leading `~` is expanded. Failures come back as tool
errors. Parsed drawings are cached by path and modification time. Large results
are capped and carry `"truncated": true`.

| Tool | Arguments | Returns |
|---|---|---|
| `open_dxf` | `path` | Version, units, extents, layer and entity counts by type, unsupported counts, warnings |
| `list_layers` | `path` | Layers with color, on/frozen state and entity count |
| `list_entities` | `path`, `layer?`, `type?`, `limit=500`, `offset=0` | One page of entities with geometry, plus `total` and `next_offset` |
| `get_extents` | `path`, `layer?` | Bounding box (`min`, `max`, `width`, `height`) and units |
| `measure` | `path`, then either `from` + `to` (`[x, y]`) or `layer?` / `type?` | Point-to-point distance, or total length of the matching entities |
| `find_text` | `path`, `query`, `limit=200` | TEXT/MTEXT matches (case-insensitive) with position, height, rotation, layer |
| `render_png` | `path`, `width=1600`, `height=1200`, `layers?`, `bbox?`, `background` (`dark`/`light`), `output_path?` | The PNG as an image, plus a summary |
| `show_in_viewer` | `path`, `layers?`, `bbox?` | Opens the file in the RustyDxf window (starting it if needed) and returns its state |
| `get_viewer_state` | — | File, visible world rectangle and layer visibility of the running window |

All tools are annotated read-only except `show_in_viewer` (changes the window)
and `render_png` (its optional `output_path` writes a file).

The live tools talk to the window over a local socket (Unix domain socket in a
`0700` directory with a `0600` socket; on Windows a named pipe restricted to the
current user). The status bar shows **MCP live** while a client is connected.

Two environment variables help with testing and headless hosts:
`RUSTYDXF_INSTANCE=name` uses a separate IPC endpoint, and
`RUSTYDXF_NO_LAUNCH=1` stops `show_in_viewer` from starting a window.

### Verification

`app/tests/mcp_stdio.rs` spawns `rustydxf --mcp` and runs `initialize`,
`tools/list` and every tool, checking that `render_png` returns a valid PNG of
the requested size.

Checked with MCP Inspector 2.15.0 in CLI mode on macOS (2026-11-14):
`tools/list` returns all nine tools with their schemas, `get_extents` returns
structured content, `render_png` returns a valid 320 x 200 PNG image block, and
a relative path comes back as a tool error (`isError: true`). The Inspector's
browser UI was not used.

```sh
npx @modelcontextprotocol/inspector --cli target/release/rustydxf --mcp --method tools/list
npx @modelcontextprotocol/inspector target/release/rustydxf --mcp   # browser UI
```

## Supported entities

| Entity | Support |
|---|---|
| LINE, CIRCLE, ARC, ELLIPSE, POINT | Yes |
| LWPOLYLINE, POLYLINE (2D) | Yes, including bulges |
| SPLINE | Yes (NURBS from control points; fit-point-only splines are approximated) |
| TEXT, MTEXT, ATTRIB | Yes (see limitations) |
| INSERT | Yes: nested, scaled, rotated, mirrored, arrays, with a recursion guard |
| HATCH | Solid fills are filled; pattern hatches draw the boundary only |
| DIMENSION | Drawn from its anonymous block |
| SOLID, TRACE, 3DFACE, LEADER | Yes |
| Everything else | Skipped and counted by type in the status bar and in `open_dxf` |

Colors: full ACI table, BYLAYER, BYBLOCK and true color. ACI 7 is white on a
dark background and black on a light one. Layers that are off or frozen start
hidden.

## Known limitations

- **Windows and Linux are untested on real machines.** The code type-checks and
  passes clippy for `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu`,
  but registration, the named pipe and the windowing have only been run on macOS.
- **macOS `--register`** has not been exercised end to end during development.
- **Text** uses one built-in font. On screen it is drawn by egui; in
  `render_png` it is drawn as filled glyph outlines. SHX/TrueType styles, width
  factors and MTEXT inline formatting are ignored, and Aligned/Fit
  justification is approximated.
- **Fit-point-only splines** are approximated with a Catmull-Rom curve.
- Line types, line weights, pattern hatches, 3D solids, images, viewports and
  paper space are not drawn; the view is model space, top down.
- Drawings are capped at 5 million flattened entities.
- On Windows the binary is a console-subsystem program (needed for `--mcp`
  over stdio), so a console may flash briefly when the viewer starts.

## Implementation notes

- The `dxf` crate does the parsing, but it drops HATCH entities, layer frozen
  flags and some DIMENSION variants. A small group-code scanner
  (`core/src/raw.rs`, ASCII and binary) recovers those and counts unsupported
  entity types.
- winit owns the macOS application delegate and has no open-file event, so
  `application:openURLs:` is added to winit's delegate class at startup
  (`app/src/platform/macos.rs`).
- The HTTP transport is served with hyper directly.

## Icon

The placeholder icon (`assets/icon.png`, `icon.icns`, `icon.ico`) is an

accent color is the single constant `ACCENT` in `core/src/brand.rs`.
